# ADR-0012：规则以默认动作为主，禁止仅用于硬边界

- 决策日期／记录日期：2026-11-03

## 背景、决定与理由

规则层约三分之一的行含否定词（`mechanism-writing.md` 一度接近一半），其中相当一部分只写“不要”而未写默认动作，执行时无法判断该做什么，容易产生分歧和重复澄清。

决定：

1. 规则句按“默认：遇到 X 做 Y；例外：仅当 Z 改为 W；验收：检查 N”书写。
2. 否定句集中到 `AGENTS.md` 的硬边界清单（最多 8 条），每条带执行前检查动作和违反时动作。
3. 事实限定、反例、历史轶事移出规则正文，放入能力矩阵、复盘或交接。
4. 同一要求或同一禁止第二次出现时，先归因（执行偏离／要求歧义／渐进细化），提出规则修正建议与影响；经用户许可后才改写规则文件。
5. 新增 `scripts/check_rule_style.py` 做静态检查，试点范围为 `AGENTS.md` 与 `notes/mechanism-writing.md`。

理由：否定句只能排除选项，不能指出默认路径；缺默认动作是执行不确定的主要来源。用户未说明其他理由，以上推理由 agent 补充并单独标识。

**来源更正（2026-11-03）**：本记录最初未经用户确认即写入并标为“已接受”。用户指出后按“规则文件修改须经用户许可”修订。状态保持“已接受”表示用户同意按修订后的内容执行，不代表原始写入方式合规。

- 触发场景／必要假设：规则文件出现大量否定句，或执行中反复澄清同一默认动作；假设读者为 agent，需要可直接执行的默认动作。
