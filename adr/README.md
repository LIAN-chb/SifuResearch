# 决策记录

保存用户决定了什么、为什么、何时需要重新考虑。新任务先按主题查本索引，只读适用的决定；执行进度仍查 [批次交接](../notes/handoffs/README.md)，研究结论仍查底稿及原始证据。

## 主动记录规则

- 用户明确作出研究方向、范围、方法、工具、组织方式、取舍或验收决定时，agent 在当前对话内主动落盘并登记索引，无需再询问是否记录。可逆决定也记录；同一决定的连续澄清合并到同一份，避免逐句话建文件。
- 用户的一次性执行指令按交接记录；其中改变后续做法的决定同时写 ADR。机制事实不是决定，agent 的建议也不自动成为用户决定。明确决定但理由未说时记录“用户未说明”，agent 分析另行标识。
- 来源不明确、仅是试探或存在未解决分歧时记为“提议”，不作为执行依据；清楚的用户决定直接标“已接受”。接受表示决定已作出，不表示效果已验证。
- 新建前搜索现有编号与主题，取当前最大编号加一，格式为 `NNNN-主题.md`；并行写入先检查编号占用。语义未变的澄清在原文追加修订日期；实质改变决定时新增记录，旧记录标“已被 ADR-NNNN 取代”并双向链接。撤回保留原因，不删除历史。
- 落盘后同步相关执行规则／项目入口；在本批交接引用 ADR 编号。收尾核对用户本轮明确决定均有落点，在回复中链接新增或修订记录。无需新增决定时只在交接注明，不建空 ADR。
- 补录历史决定标明“历史补录”、可见来源及日期可信度；没有可定位依据的动机、选项和否决理由保持未知，不用当前想法改写历史。

## 如何积累可跨项目复用的方法

每份 ADR 标明适用范围：本项目专用／可复用候选／已在所列多个项目验证。记录触发条件、依赖假设、失效边界与复核方式。项目路径、引擎版本、符号可用性及特定解析能力是实例条件，不能据此声称适合任何项目。

方法被重复使用时，在原 ADR 追加实际案例、收益／失败和证据链接；适用条件发生实质变化则建立后继 ADR。只有得到验证的步骤才提升为通用流程或可复用技能，并保留来源。暂不另建与 ADR 内容重复的方法论库。

ADR-0003 后建立 [工具矩阵](../notes/tool-capabilities.md) 和 [方法复盘](../notes/retrospectives/README.md)：分别记录能力边界和实际经验，决定理由仍只维护在 ADR。
