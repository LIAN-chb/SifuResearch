# 机制表达：条件、阶段与未知

适用于对话回答、机制／实现文档、图和表。条件表达见 [ADR-0004](../adr/0004-以条件分支表达机制与未知.md)，主体与共性范围见 [ADR-0007](../adr/0007-明确行为主体与共性范围.md)。先写读者所问阶段的确定关系，再解释必要分支；有局部缺口时只限制受其影响的结论。

## 默认组织与验收

默认顺序为“范围与前提 → 已知规则 → 相关条件分支 → 具体未解项”。只有一条规则时用一句或一段说清，不必机械生成四个标题；不存在的分支或缺口不为凑结构添加。

在已界定范围内，已知且相关的因素完整交代，写明条件、作用和结果；不能只挑一条例外得出总体“不一定”。需要表示未知时，同处说明“已知到哪里／具体缺什么／影响什么／下一步查什么”；可引用既有具名缺口，不重复长篇底稿。

回答或发布前由 agent 逐处复核不确定措辞，将已有条件可解释的模糊句改成条件关系，将真正未知定位到缺口。检查结论只能是本次范围内已复核，不能声称此前全部文档已改好或未来表达自动合规。

## 先固定讨论对象

明确事件输入、对象、当前阶段与适用前提。用户说“受击”时，依据问题区分攻击尝试、命中成立、进入命中结果分类或普通硬直已应用；必要时在回答开头用一句话界定本段所指，不要求用户先理解全部内部术语。

沿实际消费者顺序组织：先前阶段的结果决定是否进入本段，当前阶段决定本段状态，后续阶段处理退出、恢复或再次行动。没有代码依据时保留阶段接口待查，不预设所有系统具有同一执行顺序。

## 多主体与共性规则

玩家与敌人共同出现时，优先直接写“玩家”“敌人”，同场多个敌人按实例区分。每个动作、判定、回调、状态变化都应能识别“谁触发、谁判定或执行、读谁的数据、结果作用于谁”；系统执行的修改写清目标实例。主语切换时重写主语，不让读者沿用上一句主体。

攻击方／防守方／原攻击者是事件角色，会随事件切换；先映射为本事件中的玩家或具体敌人。`Owner`、`Instigator`、`Target` 首次出现时根据调用和引用说明实际归属，不能凭变量名认定谁是攻击者。未核清时明确哪一个对象引用尚未接通。

状态、计数、计时器和判断条件注明归属。不要仅写“硬直结束后允许防御”，而应在证据支持下写清哪个角色的硬直结束、哪个角色获得许可，以及许可由哪个实例或组件查询。不能为补齐句子而猜造这些归属。

共性机制明确写“玩家与敌人共用”，或写实际证据支持的对象范围；统一规则可定义“当前角色实例＝本次规则正在处理的玩家或敌人实例”，随后使用这个称谓，避免同一段中的“角色”时而指玩家、时而指敌人。共用判定函数、相同计算方式、相同参数和相同最终行为是不同层次，分别说明已核实哪一层。

先讲共用逻辑，再按需列玩家／敌人的参数、覆写和专属分支；具体事件仍说明谁对谁做什么。只确认玩家、只确认敌人或只有共享类型证据时，明确当前范围，不宣称双方完整共用。适用对象未查齐就把该范围作为缺口，不模糊已核实对象的规则。

表格列名和图节点／连线也标明主体、条件归属和作用对象。可在同一图表的说明中定义统一主体，不依赖其他章节的隐含身份；只有主体始终唯一明确时才自然省略，不机械给每句添加重复名词。

## 已知规则用条件和结果表达

1. 先给出当前证据支持的规则及前提。已证明的条件关系直接陈述，不因其他分支存在而把整句降为“可能”。
2. 同阶段确有多分支时，逐项写明判定条件、读取时机、处理结果和证据位置；有优先级或短路时写执行次序，不能用无序因素清单代替算法。
3. 与当前结论相关的上游入口条件单独说明；后续恢复或新一次行动放在对应阶段。只有确有证据说明影响当前判定时才引入，不能以“也许会招架”等想象性例外兜底。
4. 分支覆盖完整才称穷尽。只查了部分函数、样本或路径时，指出剩余未查入口及其影响，不编造全部条件。

分支较多时可用“条件／执行位置 → 结果 → 证据／缺口”的表；简单规则用连贯文字即可。详细偏移与反汇编继续留底稿。

## 把不确定性定位到具体问题

| 类型 | 应当写什么 | 如何继续 |
|---|---|---|
| 规则已知，场景输入未给定 | 已知分支条件及各自结果；明确缺少哪个场景参数 | 获取该参数，或保持条件分类，不用无条件结论 |
| 因素已定位，判定规则未恢复 | 已知字段／接口和作用阶段，缺少的比较、单位、优先级或消费者 | 定向追该判定；其余已证实链路正常讲清 |
| 规则已知，运行时取值或调用顺序未观察 | 哪个实例值、上下文或时点尚未观察，以及它影响哪一分支 | 设计最小观测；静态条件关系仍可明确表述 |
| 随机／竞争逻辑有直接证据 | 随机入口或竞争条件、已知范围；概率未知则明确未知 | 查随机参数与调度，不以“随机”概括尚未研究的行为 |
| 未定位原因 | 当前可以确认的输入／结果、尚未覆盖的调用者或范围 | 写“此处原因尚未定位”，列有依据的调查方向；假说单列，不当成已有因素 |

列出因素不等于填补缺失规则或观测；未知项必须有明确对象、影响范围和取证目标。只有真实相关且未解决的内容进入缺口说明，不在每段重复笼统免责声明。

## 表达示例：受击与防御

以下只示范论述结构，不新增《师父》机制结论。

难以理解的写法：“敌人受到攻击也不一定硬直，因为它可能招架、闪避或有其他状态。”这没有界定“受到攻击”发生在哪个阶段，也没有说明这些因素如何参与当前判定。

更清楚的组织方式：

- 若讨论“攻击能否产生普通硬直”，先按证据列出命中／防御结果分类及通向普通硬直的条件；每条路径分别说明结果。
- 若讨论“普通硬直已应用后怎样处理”，直接讲该路径的状态更新、持续和退出规则。只有证明防御操作能在这一阶段介入，才在本段讨论它。
- 若实际入口顺序或介入条件尚未查明，准确写出哪个接口未接通；不以此否定已查明的硬直内部处理，也不把未经证实的阶段关系说成定论。

## 发布前自查

- 每个谓语能否定位主体与作用对象，条件／字段归属是否明确？主体切换、事件角色和Owner引用是否映射清楚？
- 共用机制是否明确适用范围？是否混淆共享逻辑、参数相同与行为相同，或将一方证据外推到双方？
- 本段究竟回答哪个事件阶段？是否先给出了有依据的条件关系？
- 每个“可能／不一定／取决于”后面，是否已有具体条件、结果或未查项？纯粹表示未定输入时是否可直接改写成分类？
- 是否混入其他时刻、其他对象或无证据因素，令当前确定规则变含糊？
- 已知分支、未定输入、未知规则和未做观测是否分开？是否虚称覆盖完整？
- 图表与正文是否采用相同条件与顺序？局部缺口是否只限制真正受影响的结论？

此检查检验组织与可读性；机制正确性仍依赖原始证据。修改既有文档时按任务范围逐项修正，不机械删除所有限定词。
