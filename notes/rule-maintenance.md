# 规则维护流程

本流程适用于审查、修改协作规则与规则治理工具。只读讨论先提供方案；获准实施后建立治理批次并登记 [交接索引](handoffs/README.md)，记录目标、完成条件、写入范围和停止位置。纯规则维护的机制验证项标为不适用。

## 加载与分层

- 根 [AGENTS.md](../AGENTS.md) 维护始终生效的边界和任务触发入口；专项操作规则归入对应流程，事实与进度归入各自权威文档。
- 通用偏好归用户级规则。新增目录级 AGENTS.md 前确认其确有独立的目录适用约束；跨目录流程优先按任务触发读取。
- 每条导航写明触发任务及目标文档。维护时逐条登记原条款的保留、迁移或合并位置，并检查授权、只读、备份与取证边界仍可沿入口到达。
- 同一主题集中维护一处权威规则，其他入口引用该位置；项目导览解释分工并链接权威流程。

## 规则信号与决定

1. 审查或修改规则时读取交接中最近五条规则信号；不足五条时以已有记录为准，按问题识别重复标签。
2. 任务中发现规则信号时，按 [交接模板](handoffs/TEMPLATE.md) 即时记录。规则信号的记录只触发当前任务所需条目，相关历史聚合在规则维护时执行。
3. 同一要求或限制第二次出现时先归因：执行偏离、要求歧义或渐进细化；提出修正建议与影响。类型及标签的事件计数、候选阈值沿用 [ADR-0013](../adr/0013-规则信号即时记录与事件计数.md)，聚合工具为 `scripts/scan_rule_signals.py`。
4. 候选经用户许可后改规则；用户决定的 ADR 草稿、单独落盘许可与编号维护统一按 [ADR 约定](../adr/README.md)。用户选择暂不记录时在交接说明，保持 ADR 原样。

## 写法与验收

- 新规则写成默认动作；确需禁止句时集中写入所属流程的硬边界，附检查动作及违反时动作。
- 修改前检查 Git 差异并备份当前文件，迁移规则时核对每条原要求的适用范围与新位置。
- 修改后运行 `python -B scripts/check_rule_style.py`，旧报告先备份；报告固定写入 `inventory/rule-style-verification.json`。新增专项规则文件同步加入检查范围。
- 该脚本检查否定句是否配对、比例与跨文件重复，仅属形式检查。人工复核加载触发条件、条款归属与可执行性，并检查本次涉及的 Markdown 链接。
- 同步 PROJECT 的入口及 [用户导览](../Sifu/项目工作流与规则.md)；治理进展登记交接索引，机制进度页只承载机制研究状态。
- 提交按 [版本管理](version-control.md) 执行；共享文件含其他任务改动时先分流，原暂存区保持可追溯。
