# ADR-0013：规则信号即时记录与事件计数

- 状态：已接受。
- 决策日期／记录日期：2026-11-03（用户逐条确认方案后授权执行）。
- 决策者与来源：用户提出“规则要能良好迭代”，并指出跨批计数不覆盖同一轮内的重复、单次对话存在上下文遗忘；决定内容由 agent 整理，用户看过方案后确认。
- 适用范围与主题：本项目规则维护；可复用候选。

## 背景、决定与理由

原有规则变更依赖用户当场指出，且按批次汇总：无法覆盖同一批内的重复，也不抵抗上下文遗忘。改为以事件为单位记录。

1. 规则信号在发生时即时追加到当批交接，不等批末汇总。
2. 计数单位是事件而非批次；同一“类型＋标签”累计 2 次成为规则候选。
3. 同一批次内出现 2 次时立即提出候选，不再等待跨批。
4. 开工时先读最近 5 条信号，用于识别近期高频标签。
5. 候选落盘仍需用户许可；只问“是否记录”而不给草稿要点不算询问。
6. 本期只做采集、聚合与候选；淘汰与度量自动化留待信号积累后再定。

理由：用户明确指出，若只在跨批重复时才修订规则，会漏掉同一轮内已经失效的规则；而 agent 在长对话中会遗忘，记录必须外部化到磁盘，并能在开工时读到。

## 复用条件与重新评估

- 触发场景／必要假设：规则层需要持续演进，且变更须经用户许可。
- 已验证案例与证据／尚未验证：本批只验证采集与聚合，尚未产生真实候选。
- 不适用条件／重新评估触发：信号量足够后评估淘汰与度量；若即时记录在实践中难以执行，重新评估记录时机。
- 历史关系：延续 ADR-0012（规则修改须经用户许可），不取代。
