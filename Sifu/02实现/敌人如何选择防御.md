# 敌人如何选择防御：简要实现

[[00索引/首页|返回首页]] · [[00索引/术语与证据说明|术语与证据]] · [[01机制/敌人如何选择防御|阅读机制]]

本页保留理解机制所需的数据与执行入口，详细反汇编和偏移留在研究底稿。静态核对不等于实战验证。

对应：[[01机制/敌人如何选择防御|机制说明]]。

核心路径是：预测来袭攻击 → 判断是否需要防御 → 取得当前情境防御配置 → 测试并选择节点 → 验证、应用请求。

收到攻击时会记录一类 AI 记忆；攻击记忆测试读取同一类记录，按年龄、攻击属性和其他标记筛选，再比较数量。记忆年龄由每次更新的时间增量累加，因此配置中的 2、3、5、10 对应秒级窗口。

测试序列必须按各测试及其反转条件通过，关联的下一节点才有资格被遍历，仍需考虑概率和候选选择。部分反转字段未序列化；本轮已由基础测试类构造、布局和属性反射补证原生默认false，但具体资产仍可覆写，不能据单个记忆条件宣称必然选中某个反制。

格挡和弹开节点分别调用对应防御类型。部分招架成功节点配置了 `BP_AiLaunchCounterCombo_Parry` 反击动作，其完整执行条件尚未全部追通。

事件收尾也有条件：相关回调检查的是 AI 自己是否仍处于硬直，不能因为事件名包含“对手攻击结束”就误认成检查玩家硬直。

## 数据与逻辑对照

| 作用 | 入口 | 结论边界 |
|---|---|---|
| 防御需求与预测 | UpdateDefenseNeed → IsDefenseNeededInternal → ComputeIncomingAttackPrediction | 预测未要求防御时可提前退出 |
| 情境图选择 | PickContextualDefense、TestNodeForContextualDefense | 图中存在条件、概率和候选竞争 |
| 收到攻击记忆 | UpdateAttackReceivedMemory，记忆类型 3 | 与闪避成功记忆类型 2 分开 |
| 记忆筛选 | UAttackMemoryInfluenceTest::RunTest | 按记录年龄、攻击标签／掩码等计数 |
| 记忆年龄 | TickComponent DeltaTime → UpdateMemory | 逐帧累计年龄并按生命周期清理 |
| 多测试组合 | UAIInfluence_TestSequence::RunTests | 逐项应用反转，再共同决定序列通过 |
| 防御切换时中断攻击 | ComputeDefenseRequest → OnDefending | 换节点时可取消等待动作，以 Defending 结束连段 |
| 格挡／弹开执行 | HandleGuard | Guard=1、Deflect=2；分支中也可设置 None=0 |
| 闪避执行入口 | ActivatePendingAvoidWindows | 激活待处理窗口，不是直接给敌人施加长硬直 |
| 防御结束清理 | OnDefenseFinished | 清理动作、黑板、条件动作及临时数据 |

部分记忆测试未保存 m_bInverted；原生基础测试类默认false已补证，具体定位见综合实现E07及默认值表。m_HitTypes 的数值掩码符号含义仍待查，不能借用 EHitType 名称解释。

## 恢复动作的一个条件分支

| 条件／动作 | 已核对结果 | 范围 |
|---|---|---|
| 持续状态时间归零，且条件恢复动作成功安排 | 将关联动画订单剩余时间设为 0.5 秒，并通过回调否决本次到期 | 仅该条件分支；不是通用硬直／追击窗口 |
| 没有成功安排条件动作 | 此回调不否决到期 | 仍需考虑调用方和其他状态逻辑 |
| 对手攻击结束时招架节点检查 IsStun | 检查 AI owner 的受击组件 | 不是检查玩家仍在硬直 |
