# ADR-0002：以持久记录接续长期研究

- 状态：已接受；历史补录。
- 决策日期／记录日期：2026-10-28／2026-10-29。日期依据本对话此前的客户端日期与交接记录，非独立审计的聊天时间戳。
- 决策者与来源：本对话用户提出长期项目、跨对话丢失上下文及重复解包风险，讨论补充风险后明确指令“你来完善规则”。落实情况见 [20261028-协作规则-01](../notes/handoffs/20261028-协作规则-01.md)。
- 适用范围与主题：可复用候选；长期研究续接、防重复处理和证据维护。当前项目有实际记录，跨项目收益未验证。

## 背景、决定与理由

用户担心新对话缺少先前上下文，导致重复解包、无目的重读或只凭摘要形成片面理解。决定以本地规则、已有产物清单、可追溯证据链和批次交接支持续接，要求 agent 完善相关纪律。

具体流程由 agent 在授权范围内落实：处理前判断复用，保留失败和重试条件，结论变化时追查引用，多个对话检查写入范围。不是用户逐条设计所有字段，也不是已经完成全部历史审计。已有对话记忆可作线索，重要判断仍回查文件和原始证据。

## 影响与执行位置

[研究续接流程](../notes/research-workflow.md)维护处理判断，[交接索引](../notes/handoffs/README.md)维护执行断点；机器事实在 manifest，推导在底稿，研究状态在进度页。需要额外维护少量索引与交接；避免复制全量台账和为了接手例行全量重跑。

既有核查范围与未核历史见首份交接及其报告。本批没有重新验证全部资产和历史命令，也没有为此重跑解包。

## 复用条件与重新评估

适用于产物可持久保存、任务跨批次且重复处理成本明显的研究。具体 manifest、构建指纹和解析边界应按引擎／封装格式重新定义，不照搬当前 EXE/PDB 或 UE 资产假设。若频繁出现记录与产物不符、并行覆盖或索引失效，重新评估记录和同步方式。

历史关系：与 [ADR-0001](0001-主动记录用户决策.md)互补；本记录保存续接流程的选择缘由，ADR-0001保存主动记录决定的要求。
