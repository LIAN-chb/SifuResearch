## 1. 票据实例的创建

`FAIAttackTicketManager::CreateAllAttackTickets` RVA 0x184b3a0（642 字节）：

- 先清空管理器的票据数组（+0x118 数据、+0x120 计数）。
- 调 `UTicketSettings::GetTicketConfigCount()` 得到条目数，逐条 `GetTicketConfig(index, &enumOut)`。
- 再用 `FWuguanAIManager::GetOverrideAttackTicketConfig(enum)` 取运行时覆盖；非空则替换该条目配置。
- 若配置 +1 字节（常可用标志）非零：只建 1 张票据。
- 否则调 `FAttackTicketConfig::GetCount()`，按该整数建同等数量的票据。
- 每张票据由 `AddAndSetupTicket` RVA 0x18414f0（506 字节）创建并挂到管理器票据数组。

`AddAndSetupTicket` 写入位置（票据对象相对偏移）：

| 偏移 | 写入内容 | 对应配置字段 |
|---:|---|---|
| +0x30 | 防守者弱指针（`FWeakObjectPtr` 赋值；来源为管理器 +0x230 的 `m_DefenderActor`，本作正常关卡绑定玩家） | — |
| +0x38 | 票据枚举（48 字节枚举句柄） | — |
| +0x88 | 票据显示名（来自枚举 `GetDisplayFName`） | — |
| +0x90 | 配置整体复制（288 字节） | 全部 |
| +0x1B0 | 最小距离的平方 | 配置 +0xC0 最小距离 |
| +0x1B5 | 常可用布尔 | 配置 +1 |
| 其他 | 常可用为假 → 调虚槽 +0x38；为真 → `FAITicket::SetEnabled(true, true)` | — |

结论：配置里的“数量”只决定管理器内该票据的实例张数；常可用票据固定 1 张。它不等于全场同时攻击人数。

## 2. 申请入口

`FAIAttackTicketManager::RequestPassiveTicket` RVA 0x1865730（153 字节）：

- 请求者非空且是 `AFightingCharacter` 时，调 `AIHelpers::IsCharacterOnPOI(requester, &flag)`；该布尔为假则直接返回失败。
- 否则转发 `RequestPassiveTicketInternal(name, requester, bFlag, enumOut)`。
- 该外层包装不检查冷却、角色掩码或数量上限。

`RequestPassiveTicketInternal` RVA 0x18657d0（2103 字节），流程：

1. 遍历候选者数组（管理器 +0x108/+0x110，每项 16 字节，取虚槽 +0x18 得到 Actor），按请求者在数组中定位下标；找不到即失败。
2. 遍历票据数组（+0x118/+0x120），按“票据枚举相等 + 防守者相等（同属玩家这套票据组）+ 票据启用字节（+0x18）非零 + 所有者弱指针为空 + 常可用（+0x1B5）为 1”筛出第一张可发票据。
3. 从 `UTicketSettings` CDO 读 +0x1D4 浮点，平方后作为本次的最小距离阈值（用于第 4 步行为 2 的取消筛选）。
4. 按票据配置 +0xCC（即票据 +0x15C）分三支——该字段在配置结构中是“对 Joker 行为”：
   - 0：不做情境检查，进入发放。
   - 1：`ForeachJokerSituation` 回调写一个布尔；若有情境命中 → 返回失败。
   - 2：调 `IsJokerSituationActive(4)`（候选者正在攻击情境）。
     - 命中：可遍历攻击者候选，筛出“标记为攻击中、Actor 不是当前防守者（玩家）、攻击行为状态==2、与防守者（玩家）距离不小于阈值、未在名单内”的候选，逐个 `FAIAttackHandler::EndCombo("Cancelled by Pa…")` + `UAIFightingComponent::ReleaseAttackTicket`；随后仍返回失败，请求者拿不到票据。内层有一个布尔参数为真时跳过取消循环。
     - 未命中：`ForeachJokerSituation` 统计命中数；只要不为零就返回失败；为零才继续发放。
5. 发放：若内部布尔参数为假（跳转前 `[rbp+0xD8]` 为 0），调 `FAITicket::SetOwner(候选者共享引用)`；同一循环还给输出参数复制票据配置 +0x70..+0xBF 的 80 字节。

未尽事项：外层不验证冷却，冷却由“票据启用字节”间接体现；`IsCharacterOnPOI` 的 POI 具体含义未在本批取证。

## 3. 评估后指派

`FAIAttackTicketManager::OnEvaluationFinished` RVA 0x185d6a0（1308 字节）：

- 遍历待评估票据数组（管理器 +0x220/+0x228，每项 16 字节共享引用）。
- 若 `IsJokerSituationActive(4)` 为真：对该票据调用虚槽 +0x38（与建卡时非常可用票据同一虚槽），跳过、不指派。
- 否则按票据枚举把候选下标收进 `TMap<枚举, TArray<int32>>`（键 48 字节、值数组）。
- 调 `FAITicketsEvaluation::GetTicketCandidatesScores(outScores, intIndex, bool)`；对分数数组 `IntroSort` 后从末位（最高分）开始取候选。
- 已在该票据组内分配过的候选下标跳过；`FAITicket::SetOwner` 成功后把下标加入组数组。
- 随即构造 `FAIComboLaunchParameters`（含票据枚举 48 字节、重复次数）并 `FAIAttackHandler::LaunchCombo`。
- 重复次数：当票据 +0x138（配置相对 168，重复标志）非零时，取配置 +0x140..+0x148（相对 176、184）区间内的随机整数。
- 一轮结束仍无候选：对该票据调用虚槽 +0x38 重置冷却。

结论：存在两条发放路径——“请求者主动申请”和“管理器评估后指派”。评估指派一次只给每张票据一个所有者，并立即启动连段。

术语说明：代码把票据组所属的被攻击目标叫“防守者”（管理器字段 `m_DefenderActor`）。本作正常关卡只有玩家与敌人两方，防守者即玩家；敌人是攻击者／候选者。管理器在何时绑定玩家（`SetDefender` 的调用点）本批未追，属实现层未闭合，不影响此读法。

## 4. 持有与覆盖

`FAIAttackHandler::CanOverrideWithTicket` RVA 0x187c280（321 字节），参数为（票据枚举、三个布尔、输出结构指针）：

- 攻击处理器 +0x1B0 的当前票据枚举为空 → 返回真。
- 与当前票据同名 → 返回假。
- 取 `UTicketSettings` CDO，按传入枚举 `GetTicketConfig`；无配置 → 假。
- 配置 +0 行为为 0 → 返回真。
- 否则计算三个条件：传入布尔甲 且 `GetAttackBehaviorState()==2`；传入布尔乙 且 `IsAttackInputAvailable()`；传入布尔丙 且 `IsAttacking()`。任一为真 → 真，否则假。

`FAIAttackHandler::ReleaseOwnedTicket` RVA 0x1898660（230 字节）：

- 读 +0x1B0 票据枚举；空则直接返回。
- 非空则构造 `FAIComboLaunchParameters` 并调 `LaunchCombo`，不直接改动管理器票据数组。

结论：这个名字的函数走的是“重新发起连段参数”而不是清空全局票据。

## 5. 释放

`FAIAttackTicketManager::ReleaseAITicketsInternal` RVA 0x18641e0（374 字节）：

- 遍历管理器票据数组。
- 先按票据枚举筛选（枚举指针相等，或退化为四个字段逐项相等）。
- 再取票据所有者弱指针，虚槽 +0x18 得到 Actor，与传入 Actor 比较。
- 两者都匹配时调票据虚槽 +0x28，参数为 1。
- 不匹配的票据完全不动。

结论：释放是“按票据名＋持有者”定向释放，不是清空全部票据；从该函数看不到“另一名敌人随即获得票据”的动作。

`FAIAttackTicketManager::GetCandidateOwnedTickets` RVA 0x1851200（308 字节）：遍历票据，所有者等于传入 Actor 即把票据枚举（48 字节）追加到输出数组。这是“查询某人持有哪些票据”的入口。

## 6. 冷却

`FAIAttackTicket::TickCooldown` RVA 0x186dc60：票据 +0x1B4（配置相对 436，冷却暂停标志）非零时直接返回假；否则尾调 `FAITicket::TickCooldown`。

`FAIAttackTicketManager::SetTicketEnabled` RVA 0x1868c40（545 字节）是管理器对基类同名函数的覆写：

- 关闭票据：直接走基类 `FAITicketManager::SetTicketEnabled`。
- 开启票据：若票据 +0x130（配置相对 160，同步容差）不大于 0，直接走基类。
- 否则在“同名且非自身”的票据里找 +0x28（double，上次时间戳）最大且大于 0 的一张；计算当前时间（`QueryPerformanceCounter × SecondsPerCycle + 16777216.0`）减去该时间戳。
- 若差值 ≥ 本票据 +0x130（同步容差）→ 走基类正常开启。
- 否则遍历同名票据：虚槽 +0x20 返回假（即当前可用/未在冷却）者，调 `FAITicket::AddToCurrentCooldown(票据 +0x12C)`，即同步偏移秒数。
- 票据 +0x12C 与 +0x130 分别对应配置相对 156、160，即既有类型记录中的“同步开火冷却偏移／容差”。

`FAIAttackTicketManager::SetTicketsCooldownTimer` RVA 0x1868e70（282 字节）：按票据枚举筛选后对每张调 `FAITicket::SetCooldownTimer(seconds)`。

既有证据（`notes/group-ai-state.md`）已接通 `FAIAttackTicket::ResetCooldown` → 读难度阶段 → `FAttackTicketConfig::GetCooldownFromGaugeStep` → `FAITicket::ResetCooldown`。本批未新增难度标签映射。

## 7. 评分与测试

- `FAIAttackCandidate::ComputeTestFactors` RVA 0x184a9a0（782 字节）：清空候选因素表后，要求候选者是 `AFightingCharacter`、其 AI 战斗组件 +0xF8 非空，然后调 `UAIFightingComponent::GetAttackTicketEvaluationFactors(TMap<EAIWuguanTicketEvaluation,float>&)`；把该映射的键转成枚举名写入候选自己的因素表（`TMap<FName,float>`）。
- `FAITicketManager::RegisterTest` RVA 0x1897ad0（621 字节）：每个测试默认分数 1.0（`0x3f800000`），存入管理器 +0x18 的 `TMap<EAITicketTest, TArray<FAITicketTestRefWithScore>>`；对测试类型 3／4 另查管理器虚槽 +0x38 的覆盖分数；同时写入 +0x68 的（测试,分数）集合。
- `FAITicketCandidateEvaluatorFunctor::Evaluate` RVA 0x18827d0（253 字节）：把实际打分委托给本对象虚槽 +0x30，把返回浮点写入评估请求 +0x10，并置 +0x14=0x101、+0x28=2。
- `FAITicketManager::EvaluateCandidates` RVA 0x18829e0（1268 字节）与 `EvaluateCanditatPerTicket` RVA 0x1882ee0（1431 字节）：做请求收集、`MaxTimeReached` 超时检查、结果数组扩容、`StartAsyncJobIfNeeded`；未见固定权重常量。
- `FAITicketManager::FilterCandidates` RVA 0x1884a40（2061 字节）：`FetchAsynchTasksResults`、`GetRequests`、`IntroSort` 下标数组、再 `StartAsyncJobIfNeeded`。

结论边界：评分是“因素映射 + 每测试权重（默认 1.0，可被类型覆盖）+ 评估器子类求和”，但具体权重表与子类实现不在本批符号内，数值结论留给后续。
