# 工作区目录约定

适用于新增文件、文件迁移、目录整理和任务收尾。根目录作为入口，项目现有职责目录保持稳定；目录说明见 [README.md](../README.md)。

## 文件归属

| 文件用途 | 默认位置 |
|---|---|
| 项目入口与协作入口 | 根目录 README.md、PROJECT.md、AGENTS.md |
| 必要仓库配置、客户端工具目录 | 根目录对应配置；工具约定的固定目录保持原位 |
| 决策与理由 | adr/，按其单独许可流程写入 |
| 可复用流程与主题底稿 | notes/ |
| 批次规格、任务清单、验收清单 | notes/batches/<批次ID>/ |
| 批次状态、断点和写入范围 | notes/handoffs/<批次ID>.md |
| 提取、解析与取证的运行产物 | exports/<批次ID>/、logs/<批次ID>/；研究细则见研究流程 |
| 可重复执行的脚本与工具 | scripts/、tools/ |
| 知识库正文与发布页面 | Sifu/ 对应主题目录 |
| 原始定向提取、清单与索引 | extracted/、inventory/，按既有生成工具及研究流程维护 |
| 临时试验与备份 | 系统临时目录或批次 logs/exports 下的独立目录 |

新文件先按用途选择现有目录；新增一级目录时说明独立职责及现有目录无法容纳的原因。跨项目通用规则与本项目文件归属分开维护。

## 迁移与收尾

1. 检查实际文件、Git 状态及相关批次的写入结束标记；确认来源、用途与当前归属。
2. 搜索路径、文件名及生成脚本引用；检查目标路径位于研究根目录内且目标未被占用。目标不明或有写入冲突时先保留原文件并记录待处理项。
3. 迁移前备份；保留清单，登记原路径、新路径与哈希。历史规格正文保留历史身份；必要的当前链接按新位置修正。
4. 迁移后核对内容哈希及相关链接，确认原路径已释放、生成工具仍使用有效路径。
5. 收尾列出根目录内容，确认入口、配置及一级目录各有职责；本批遗留的任务文件、报告和临时文件归入对应子目录。工具生成的固定隐藏目录按工具用途判断。
