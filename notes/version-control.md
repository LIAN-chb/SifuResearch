# 本地版本管理

本项目于2026-10-29建立本地 Git 仓库，分支 `main`。初始提交是当前文件状态的基线，不恢复此前未提交的历史；初始提交编号见 `git log -1` 和本批交接。没有设置或推送远程仓库。

## 保存什么

`.gitignore` 是实际纳入范围的依据：保存根规则、ADR、方法复盘、脚本与模板、知识库正文／发布页／手工图和作为检查配置的 `inventory/vault-layout.json`；保留 `tools/local_bounded_packages.py` 和 `exports/` 中非备份目录下的 Python 源码。这些 Python 文件是处理工具源码，不是解析数据。默认忽略其他顶层目录及未明确纳入的库存数据。

原始提取、游戏二进制、第三方下载、解析数据、自动生成的概览／批次清单／验证报告、原始日志、历史备份和 `.obsidian/` 配置不纳入。来源与哈希清单仍保留本地，用于复用和核查；Git回退不会重建它们，因此这不是完整资产备份或灾难恢复方案。已有源文件若被忽略，先明确其角色，再调整范围或逐项纳入。

## 每批如何使用

1. 开始前用 `git status --short` 和相关路径的 `git diff` 确认已有改动，避免把其他对话的工作纳入本批。
2. 通过适用检查后，用 `git add -- <本批文件路径>` 显式暂存；检查 `git diff --cached --stat` 和差异，再提交。多批并行时不使用无差别全量暂存。
3. 本批提交完成后在交接记录提交编号或可定位的提交主题；尚未纳入版本历史的文件明确标注。初始基线因不存在先前提交，包含初始化时的当前文件状态。
4. 需要恢复文件时先查看目标提交差异并保存当前未提交修改；覆盖或回退共享内容前检查其他进行中批次。不要把清空工作区作为日常收尾手段。

新批次通常由 agent 在完成验证后主动提交本批改动；本地提交不代表发布。远程创建／推送和全资产备份另行决定。本批若本机缺少 Git 身份，使用仅本次提交的 `Codex <codex@local.invalid>`，不修改全局身份；实际使用身份见提交记录。
