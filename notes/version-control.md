# 本地版本管理

本项目于2026-10-29建立本地 Git 仓库，分支 `main`。初始提交是当前文件状态的基线；此前未提交的历史保持在原处。初始提交编号见 `git log -1` 和本批交接。当前使用本地仓库，远程创建与推送另行决定。

## 保存什么

`.gitignore` 是实际纳入范围的依据：保存根规则、ADR、方法复盘、脚本与模板、知识库正文／发布页／手工图和作为检查配置的 `inventory/vault-layout.json`；保留 `tools/local_bounded_packages.py` 和 `exports/` 中非备份目录下的 Python 源码。这些 Python 文件按处理工具源码纳入，与解析数据分开。

原始提取、游戏二进制、第三方下载、解析数据、自动生成的概览／批次清单／验证报告、原始日志、历史备份和 `.obsidian/` 配置保留在本地但不纳入版本历史。来源与哈希清单仍保留本地，用于复用和核查；Git 回退只覆盖已纳入的文本，资产备份和灾难恢复另行维护。已有源文件若被忽略，先明确其角色，再调整范围或逐项纳入。

## 每批如何使用

1. 开始前用 `git status --short` 和相关路径的 `git diff` 确认已有改动，并按对话来源分流本批与他批。
2. 通过适用检查后，用 `git add -- <本批文件路径>` 显式暂存；检查 `git diff --cached --stat` 和差异，再提交。多批并行时按路径逐项暂存。
3. 本批提交完成后在交接记录提交编号或可定位的提交主题；未纳入版本历史的文件明确标注。初始基线对应初始化时的当前文件状态。
4. 需要恢复文件时先查看目标提交差异并保存当前未提交修改；覆盖或回退共享内容前检查其他进行中批次。清空工作区只用于明确放弃全部未提交改动，执行前先确认备份。

新批次由 agent 在完成验证后主动提交本批改动；本地提交不触发发布。远程创建／推送和全资产备份另行决定。本机缺少 Git 身份时，本次提交用 `Codex <codex@local.invalid>` 临时指定，全局身份保持不变；实际使用身份见提交记录。
