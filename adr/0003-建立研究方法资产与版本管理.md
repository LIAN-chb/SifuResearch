# ADR-0003：建立工具矩阵、方法复盘、本地版本管理与阅读导览

- 状态：已接受。
- 决策日期／记录日期：2026-10-29／2026-10-29。
- 决策者与来源：用户在本对话明确要求将上轮工具能力矩阵、方法复盘、版本管理三项建议“都直接建立起来”，并在项目内 Obsidian 仓库根目录提供工作流与规则文档。
- 适用范围与主题：可复用候选；研究方法与过程治理。当前实现限 SifuResearch，跨项目效果尚未验证。

## 决定与执行

建立 [工具能力矩阵](../notes/tool-capabilities.md)、[方法复盘](../notes/retrospectives/README.md) 和 [本地版本管理](../notes/version-control.md)；用户阅读入口位于 [项目工作流与规则](../Sifu/项目工作流与规则.md)。理由沿用前文诉求：保留能力边界、失败经验及决策历史，以提高后续项目取证和理解效率。

agent 对实施方式的细化：先依据现有证据填真实案例；未知成本和跨项目效果不估造。Git纳入当前管理、源码、阅读成果及布局配置基线；原始资产、解析数据、自动生成的概览／批次清单／验证报告留在本地，不设置远程。工具样本、解析边界和项目路径不当成其他引擎的通用能力。用户随后询问解包产物是否有必要入 Git，agent 据此解释并收紧实现范围；此问句不另记为用户作出的新决定。

方法复盘保存实际经验，不重复 ADR 的取舍理由；因此对 [ADR-0001](0001-主动记录用户决策.md) 中暂不另建重复方法论库的约定作细化，并延续 [ADR-0002](0002-以持久记录接续研究.md) 的单一权威记录分工。三份记录互补，旧决定未撤回。

## 影响与复核条件

增加持续维护与批次提交成本；只记录有代表性的经验，按需读索引。本地 Git 不保护忽略的原始资产，也不能替代异地备份。若未来要保存大型资产、共享远程、跨项目维护工具库，重新决定版本范围和存储方式。实施与验证见 [本批交接](../notes/handoffs/20261029-研究管理落地-01.md)。
