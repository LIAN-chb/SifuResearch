# 执行前的能力发现与复用

决策见 [ADR-0006](../adr/0006-执行前发现并复用现有能力.md)。适用于需要专门解析、生成、转换、验证、应用操作、发布或自动化能力的任务。简单文本编辑使用已有能力，不例行全网检索。

## 1. 先明确交付，再寻找能力

明确目标、输入格式／版本、预期交付物和验收条件。复杂任务按实际需要分成处理、生成、检查等阶段，分别找能力；发现生成工具后仍要确定如何验证其输出。任务目的可从上下文判断时直接执行，不为完成表单额外提问。

## 2. 按需查找，命中后核实

1. **当前可用能力和用户指定入口**：查看本轮实际提供的工具与技能目录，尊重用户指定的工具／应用；有专用工具或已连接服务能力时优先核实使用。工具名称与权限以当前会话实际可用信息为准。
2. **项目已有实现与经验**：查 [工具矩阵](tool-capabilities.md)、[方法复盘](retrospectives/README.md)、相关脚本、模板和历史产物。当前能力与本地索引可以一并核查，不为形式机械串行搜索。
3. **必要的候选说明**：筛出适用技能后读取其实际 `SKILL.md`；工具查看接口、适用范围或必要的帮助。检查关联依赖，不凭名称、关键词或宣传摘要认定能完成任务，也不把所有技能全文读一遍。
4. **缺口明确时再扩展发现**：当前能力不足，或用户明确要求寻找替代方案时，再使用现有技能发现／安装目录、插件发现能力，必要时查询官方文档或可信来源。软件版本、兼容性等易变事实按实际来源核实。

## 3. 选择前核对的内容

| 核对项 | 需要确认什么 |
|---|---|
| 实际可用性 | 是当前可调用、已安装、本地可执行，还是仅发现候选；依赖和访问是否满足 |
| 输入覆盖 | 支持当前格式、版本、对象与处理范围；是否损失需要保留的字段 |
| 输出与验收 | 产物是否满足目标，怎样验证内容、边界、引用和布局等实际要求 |
| 代价与边界 | 运行、安装或适配成本，写入范围、外部依赖与已知失败条件 |
| 来源与维护 | 工具／技能实际来源、版本或哈希，说明与本次环境是否一致 |

未执行或未验证的候选明确标注；发现工具不等于已安装，安装不等于适用，退出0不等于完成任务。有必要时先用最小代表样本核能力，再扩大范围。

## 4. 复用、组合、扩展或自行实现

优先选择满足目标且代价合适的现有方案；可以组合工具的操作能力、技能的流程纪律、模板的产物结构及独立验证工具。既有实现只需小改时先评估扩展。

确有缺口才自行实现，在交接写明具体原因，如格式不支持、关键字段丢失、验收要求无法满足，或适配现有方案的成本高于新实现。成本未知时先做小样，不用未经验证的“更灵活／更高效”替代依据。

发现、阅读、安装、执行和外部写入分别按实际动作及现有授权处理，不将用户要求找工具误写成已经安装或使用了工具，也不重复索要已给出的授权。一个候选受阻后，先判断能否用现有能力或更小范围方案完成，再决定下一步。

## 5. 保存发现结果，避免重复搜索

本批交接记录实际查过的范围、选用能力及验收方法、未解决缺口；已有条目用链接引用。普通复用一句说明即可，不强制为每个小任务建独立检索日志。

新增能力／限制更新工具矩阵；代表性方法经验写复盘。未找到合适能力时记清查找范围、日期、输入条件和重查触发点；只能说“本次范围内未找到”，不能宣称永久不存在。

工具／技能版本、格式、依赖、访问条件变化，原方案失败、既有记录来源不足或用户要求重新查找时重新评估。条件没变且旧证据满足需要时直接复用，不每轮从头检索。

收尾核对：是否查过适用的现有能力；选择理由与验证方式是否明确；自行实现是否有具体缺口；候选、安装、执行和验证状态是否分清。向用户简要说明选用方案和材料限制，省略无关查找流水账。
